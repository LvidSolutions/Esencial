## Not secrets

`SANITY_PROJECT_ID`, `SANITY_DATASET`, `SANITY_STUDIO_PREVIEW_ORIGIN`, `CMS_ORIGIN`, `VERCEL_ANALYTICS_TEAM_ID`, `VERCEL_ANALYTICS_PROJECT_ID`, `GOOGLE_SEARCH_CONSOLE_SITE_URL`, `COOKIEBOT_CBID` and consent text/configuration are identifiers or public configuration, not authentication secrets.

## Where the code expects credentials

- `.env.example` lists the public configuration and server credential names, but contains placeholders only.
- `.github/workflows/cms-build.yml` reads `SANITY_API_TOKEN` from GitHub Actions Secrets.
- `api/draft-mode/enable.js` and preview rendering use `SANITY_PREVIEW_TOKEN` server-side.
- `api/sanity-publish.js` uses `SANITY_WEBHOOK_SECRET` and `GITHUB_DISPATCH_TOKEN`.
- `api/analytics.js` uses `VERCEL_ANALYTICS_TOKEN` and `GOOGLE_SERVICE_ACCOUNT_JSON`.

## Rotation procedure

For every manually managed credential: create replacement → update secret store(s) → run the affected staging flow → confirm success → revoke/delete old credential. Never remove the old credential first during routine rotation unless compromise is suspected.

### Manual verification still required

The repository and GitHub/Vercel connectors intentionally cannot reveal secret values or private secret metadata. Fill the real expiry dates into your private password/secret manager after checking the provider dashboards. Do **not** commit secret values here.
